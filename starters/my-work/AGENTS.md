# Working in this task workspace

- Start with the owner's goal and the last recorded outcome. Use `config.json` to find the selected project YAML files. The README explains how to validate and rebuild them.
- Keep each task's status, dependencies, and completion check in its YAML source. Preserve existing task IDs. Mark a task complete when its check passes or the owner explicitly verifies it.
- Use a short case note for work that spans multiple exchanges. Record a dated outcome, the evidence location, open decisions, and who owns the next action. Keep source documents and sensitive correspondence in the owner's chosen location.
- When picking up a task, read the relevant case note and source map. For a browser draft, compare the proposed edits with the current YAML before applying them.
- Validate and rebuild after changing a map. If Git tracking is enabled and the owner wants updates committed, commit the related source changes and case note together. Publish or sync according to the owner's sharing instructions.

## Workspace choices

The owner can record standing choices here as they start using the system. Useful choices include which repositories own which projects, the usual location for documents, whether Git handoffs are local or shared, and which branch or review process the team uses. Keep credentials in their designated secret store.
